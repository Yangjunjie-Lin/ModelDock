# RelayDock V2.0

RelayDock V2.0 is the multi-project governance release. It keeps provider
credentials, credential groups, and physical model routes under platform
administrator control, while isolating downstream API keys, route grants,
budgets, usage, logs, exports, and webhook events by organization and project.

The release preserves all V1 endpoint contracts. Existing installations are
migrated into a deterministic `legacy` organization and project, so existing
keys and model aliases continue to work.

## Scope

V2.0 adds:

- organizations, projects, organization/project membership, and project route
  grants;
- project-scoped API keys and immediate invalidation when a user,
  organization, project, or membership is disabled;
- monthly project budget policies with `WARN` or `BLOCK` enforcement and
  deduplicated warning/exceeded events;
- credential tag constraints through route `fallback_config` using
  `required_credential_tags` and `excluded_credential_tags`;
- API-key versioning with one-time rotation output, a bounded grace period,
  and explicit finalization;
- signed webhook endpoints backed by a durable, at-least-once outbox with
  retry/dead-letter state;
- project-aware CSV usage export and alert acknowledgement;
- a versioned, locked, transactional database migration runner.

V2.0 does not add cross-provider request replay, consumer web sessions,
account creation, CAPTCHA handling, proxy rotation, or promotion automation.

## Request path

```text
RelayDock API key version
  -> active user / organization / project / membership
  -> project route grant and key model allowlist
  -> key, user, and project budget admission
  -> route credential-tag constraints
  -> deterministic credential scheduler
  -> official provider API
  -> request log + daily/hourly usage
  -> budget event + transactional webhook outbox
```

The original API-key record remains the stable policy and accounting identity.
Rotations create key versions, so rate limits, budgets, permissions, and usage
do not reset when a secret changes.

## Webhook envelope

Supported events are `webhook.test`, `budget.warning`, `budget.exceeded`, and
`api_key.rotated`. Delivery is at least once. Consumers must deduplicate by the
event ID.

```http
X-RelayDock-Event: budget.warning
X-RelayDock-Delivery: <delivery-id>
X-RelayDock-Timestamp: <unix-seconds>
X-RelayDock-Signature: v1=<hex-hmac-sha256>
```

The signature input is `<timestamp>.<exact-json-body>`. Redirects are disabled,
response bodies are bounded, and production targets require HTTPS and public
network resolution unless the operator explicitly enables development-only
HTTP/private-network delivery.

## Input-to-output acceptance matrix

Every V2 test asserts the HTTP/SSE output, PostgreSQL state, scheduler reason,
upstream mock observation, audit record, and webhook side effect where
applicable.

| Capability | Input | Expected output and side effect |
| --- | --- | --- |
| Organization/project | Create org, project, member, route grant | `201/200`; stable IDs and isolated membership rows |
| Tenant boundary | Project A member requests Project B resource | `404`; no resource details or usage leaked |
| Status cascade | Disable user/org/project/membership | Existing project key immediately returns `401` |
| Project model grant | Key requests an ungranted alias | `404 model_not_found`; zero upstream requests |
| Budget warning | Usage reaches warning percentage | Request succeeds; one budget event/outbox item |
| Budget block | Project already exceeds a `BLOCK` policy | `403 project_budget_exceeded`; zero upstream requests |
| Tag routing | Require `region:apac`, exclude `maintenance` | Selected credential has required tags; reason records constraints |
| Key rotation | Rotate with bounded grace | New secret shown once; old/new work until grace ends |
| Finalize rotation | Finalize the rotated key | Old secret returns `401`; new secret remains valid |
| CSV export | Export a bounded project/date range | Accurate CSV, safe headers, no secrets or prompt content |
| Webhook success | Queue a test/budget/rotation event | Valid HMAC received; outbox becomes `DELIVERED` |
| Webhook failure | Receiver returns `500` | Attempts and backoff increase; final state becomes `DEAD` |
| Alert acknowledgement | Acknowledge an active alert | `acknowledged_at` and actor are persisted |
| V1 compatibility | Run V1 integration and official SDK suite | All previous assertions continue to pass |

## Deferred to V2.1+

- native Anthropic, Gemini, and Azure adapters;
- cross-provider cost/latency target selection;
- replay with idempotency proofs;
- distributed budget reservations with post-response reconciliation;
- retention and external secret-manager workers;
- multi-replica and Kubernetes release artifacts.

These require their own deterministic provider mocks, failure-injection suites,
and multi-replica acceptance environment rather than untested configuration
flags in V2.0.
